# 智群 · Quorum —— 业务逻辑（M0 现状整理）

这份文档只描述**现在真的跑起来的东西**：数据长什么样、命令链怎么走、每条命令执行完落到哪里。
末尾单列一节「模型撑不住的地方」，那些是要你拍板或留到 M1 的。

---

## 1. 领域模型

四样东西。计划 / 角色 / 项目落在 `data.json`（见 §7），设置另存一个文件。

### 计划 Plan —— 计划自己拥有"什么时候"和"多大声"

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | `p-1` 递增 |
| `day` | string | **日期键** `YYYY-MM-DD`，不是星期几。这样日历能翻月 |
| `start` / `end` | number | 小数小时，`9.5` = 09:30，`12.07` ≈ 12:04 |
| `title` | string | 标题 |
| `note` | string | 说明；命令链里的「项目 · 动作」也塞在这里 |
| `role` | string | **角色的名字**（不是 id） |
| `level` | `L1` / `L2` / `L3` | 提醒级别，到点走哪条通道见 §6.4 |
| `repeat` | `once` / `daily` | 每天靠前端把 dueAt 滚到下一次，见 §6.4 |
| `done` | bool | 勾掉即 true |
| `action` | `{ kind: "remind" \| "run"; prompt: string }` | 到点做什么。`remind` 只提醒；`run` 是交给角色动手 —— **字段先立住，还没有任何东西执行它**。老数据没这个字段的，载入时按 `remind` 补上 |

### 角色 Role —— 只拥有身份和权限

| 字段 | 说明 |
|---|---|
| `id` / `name` | `r-1` / 显示名 |
| `grants` | 6 项权限，见下 |

权限模板（`grantsTemplate()`）固定 6 项：日历读取、计划写入、文件读写、屏幕截图、浏览器控制、执行脚本，
每项带 `on` 开关和一句 scope 文案。**现在只是 UI 状态，没有任何地方真的校验它们。**

### 项目 Project —— 只拥有文件

| 字段 | 说明 |
|---|---|
| `id` / `name` / `note` | `pr-1` / 显示名 / 说明 |
| `paths` | 目录列表；`查看文件夹` 走 Rust 的 `list_dir` 懒加载 |

### 视图与临时状态

| 名字 | 含义 |
|---|---|
| `view.day` | 当前选中的**日期键**（默认今天），日历点一下即改 |
| `ui.drawer` | 角色抽屉：`null` / `{kind:"role", id?}` / `{kind:"role", name?}`（新建时预填名） |
| `ui.projectDraft` | 一次性通道：命令链把参数递给项目表单，表单**读一次就清空** |

## 2. 窗口与面板的骨架

- **三种窗口形态**：贴边药丸 148×44 / 展开清单 320×(34+36n+10) / 面板自适应 40%×55%（夹 760–1120 × 520–800）。
  几何归内核，前端只调 `set_mode`。
- **面板只隐藏、不卸载**：切到胶囊时面板组件仍然挂着（`display:none`），否则失焦收起会把输入框里写了一半的那句一起丢掉。
- **计划域有两种范围**：当天（默认）与「即将到来」（全部未完成，按日期时间铺开，此时日历整块收起）。右上角一个按钮来回切。
- **面板四个域**，各自一条独立的路线；顶部导航**只有后退、没有前进** —— 后退就是从这条路线上弹出最后一跳，走到底停在该域的根，不会跨域。
- **计划域的日历默认收起**成一行（当前选中日所在的那一周），收起时连月份切换那一行也一起收起来；点「展开完整日历」才铺开六行月历。格子高度按圆圈收紧到 28px（圆 21px），月历六行不再散。
- **一条计划都没有时**，列表位置给的是一段引导（"在上面输入框写一句，比如「写周报 9:30」"+ 一个新建按钮），而不是两个并排的「暂无」。

| 域 | 根路由 | 可进入的子页 |
|---|---|---|
| 计划 | `planner` | `plan/:id`（单条详情）、`plan-new`（新建表单） |
| 角色 | `roles` | 抽屉（覆盖在列表上，不是路由） |
| 项目 | `projects` | `project/:id`、`project-new` |
| 设置 | `settings` | — |

- 切标签会**清空输入框里的一切**（草稿、胶囊、命令链），因为同一个框在四个域里含义不同。

## 3. 命令链（核心）

### 3.0 纯文本的默认动作（每个域都有）

输入框下面没有菜单、也没输入 `/` 或 `@` 时，回车就是"这个域自己那件事"：

| 域 | 纯文本回车做什么 |
|---|---|
| 计划 | 解析出一张草稿条（见 §3.5） |
| 角色 | 直接开新建抽屉，这段字当名字预填 |
| 项目 | 直接开 `project-new`，这段字当名字预填 |
| 设置 | 没有可提交的东西：输入框禁用，占位符写明"这一页没有命令" |

各域输入框左边那个 **＋** 是同一件事的空版本：计划域开新建表单、角色域开空抽屉、项目域开空表单，设置域不显示。

### 3.1 两种模式

| | 触发条件 | 可用命令 |
|---|---|---|
| **模式一** | 没有选中项目 | `/新建计划` `/查看计划` `/新建角色` `/编辑角色` `/新建项目` `/编辑项目` `/执行角色` |
| **模式二** | 选中了项目（`@` 选过） | `/交给角色` `/添加路径` |

选中项目后**不能再建角色** —— 这是刻意的：项目是硬边界，链上的动作只能作用于这个项目。

列表怎么筛：`head = 输入.split(/\s/)[0]`，再对命令 id 做**子序列匹配**（字符按顺序出现即可，允许跳过）。所以 `/计` 同时命中新建计划与查看计划，`/新计` 命中新建计划；空串匹配全部，光输入 `/` 就是全部命令。以前是前缀匹配，逼着人先想起动词才能查。

### 3.2 每条命令的执行结果

都以「点开备选 → 回车」为动作，★ 表示实测过的结论。

| 命令 | 参数 | 执行结果 |
|---|---|---|
| `/新建计划` | 内容（可空） | 打开**新建表单**（`plan-new`）；填了内容就预填标题/开始/重复。**参数为空也照样打开**——所有 `/` 命令的参数都是可选的 ★ |
| `/查看计划` | — | 列出全部计划（按日期、时间排），选中即打开 `plan/:id` ★ |
| `/新建角色` | 名称（可空） | 切到角色域 → 打开新建抽屉，名称已填进去 ★ |
| `/编辑角色` | —（但会把输入框变成 `/编辑角色 `） | 列出**全部角色**，选中即打开该角色的抽屉 ★ |
| `/新建项目` | 名称、路径（都可空） | 切到项目域 → `project-new`，表单里名称和路径**都预填** ★ |
| `/编辑项目` | —（输入框变成 `/编辑项目 `） | 列出全部项目，选中即打开 `project/:id` ★ |
| `/执行角色` | — | 进入"选角色"阶段，列出全部角色，选中变成**角色胶囊** |
| `/交给角色` | — | 与 `/执行角色` **完全一样**（见 §5 的问题 3） |
| `/添加路径` | 路径（可空） | 把这段文字变成**动作胶囊**，不会写进项目的路径列表（见问题 2） |

参数**全都可以跳过**：在参数槽上直接回车 = 用已填的部分执行（`/新建项目` + 空回车 → 打开空白的项目表单）。

### 3.3 参数链的状态机

```
输入 "/"        → 列出所有命令
选中某条命令     → 有参数：进入参数链，输入框前出现蓝色命令胶囊
                 无参数：立刻执行（见上表）
填一个参数 + 回车 → 该参数变成一颗彩色小胶囊（名称=蓝 / 路径=绿 / 第三个=橙）
                   占位符变成下一个参数名
参数填满        → 执行 finish()，把参数交给对应页面
```

**Esc 逐层回退**，一层一层剥，剥完才关面板：

```
备选菜单开着  → 收菜单
有参数胶囊    → 去掉最后一个参数
只剩命令胶囊  → 去掉命令
还有 @/角色胶囊 → 去掉最后一个
全空          → 这一次才关闭面板
```

**退格**：输入框为空时删掉最后一颗胶囊。

### 3.4 `@` 的语义

- 输入 `@` 列出项目，选中后：加一颗**项目胶囊**，并且**只保留项目+角色胶囊，动作胶囊被丢掉**。
- 项目一旦选中，`@` 就**失效**（不列任何东西）——链条里不能再换项目。
- 项目胶囊决定了用哪套命令表（模式一变模式二）。

### 3.5 没有 `/` 也没有 `@` 时：写一条计划

输入框在计划域里的默认职责是"写一条计划"，按回车先出**草稿条**（不会直接建）：

| 解析 | 规则 |
|---|---|
| 时间 | 正则 `(\d{1,2})\s*[:：点]\s*(\d{1,2})?`，只写小时也算（`下午 3 点` → 15:00 不行，只认数字） |
| 每天 | 出现「每天」或「每日」→ `repeat = daily` |
| 标题 | 原文挖掉时间和"每天"之后剩下的；挖空了就退而用「动作 · 项目」，再空就是"新计划" |
| 级别 | **永远 L1**（要改就走新建表单） |
| 时长 | **永远 0.5 小时**（要改就走新建表单） |
| 归属日期 | 当前选中的那天（`view.day`） |
| 角色 | 角色胶囊，没有就写「编排」 |
| 说明 | `note = 项目 · 动作` |

草稿条上点「创建计划」才真的写入，点「取消」丢掉。

### 3.6 新建表单（`plan-new`）

两个入口：**计划页右上角的「新建计划」**，以及 `/新建计划`（参数随便填不填）。这是"精确建"的那条路，
上面 §3.5 是"随手记一条"的快路 —— 两者最后落的都是同一条计划。

| 字段 | 说明 |
|---|---|
| 标题 / 说明 | 文本 |
| 日期 | 原生日期选择器，默认当前选中的那天 |
| 开始 | 原生时间选择器。**改开始时间会带着结束时间一起平移**，刚设好的时长不会被改掉 |
| 持续 | 分钟数，默认 30 |
| 触发 | 一次 / 每天（每天靠前端把 dueAt 滚到下一次，见 §6.4） |
| 通知 | 静默 L1 / 系统通知 L2 / 强提醒 L3，三个都真的会响（见 §6.4） |
| 角色 | 下拉，选项来自角色列表 |

「创建计划」才写入；「取消」什么都不留。同一个组件也负责 `plan/:id` 详情页 —— 已存在的计划是**边改边存**，
没有保存按钮；只有新建这一侧有"创建/取消"。

## 4. 胶囊（悬浮窗）的业务

| 形态 | 内容 |
|---|---|
| 贴边药丸 148×44 | 倒计时 + 下一项标题 + 「+N」；没有任何安排时是「待命 / 今天没有安排」 |
| 展开清单 320×(34+36n+10) | 今天的全部计划：勾选框 + 时间 + 标题 + 等级 |

- **勾选 = 标记 `done`**，已完成的计划不会再触发提醒（这是"勾掉就不弹通知"的实现方式）。
- 点某一行 → 打开面板里那条计划的详情。
- 一条都没有时，清单里那句提示**本身是个按钮**，点一下就把面板叫出来（原来这里和标题徽标说着同一句话，等于废话）。
- 只有标题条能拖 —— 整块可拖的话勾选会跟拖动打架。
- 倒计时：>1 小时显示 `时:分:秒`，最后一小时 `分:秒`；已开始显示「进行中」，时间窗过了没做显示「已错过」。
- 展开/收起由鼠标进出驱动，收起后有 320ms 宽限。

## 5. 模型撑不住的地方（要你拍板）

| # | 问题 | 现在的样子 | 建议 |
|---|---|---|---|
| 1 | **计划不持有 project / role 的 id** | `role` 存名字、`note` 里拼「项目 · 动作」 | 改成 `projectId` + `roleId`；改名不断链，同名不打架 |
| 2 | `/添加路径` **没有真的加路径** | 只是把文字塞进动作胶囊，然后进 note | 要么真的 `project.paths.push()`，要么删掉这条命令 |

| 5 | 角色默认写「编排」 | 项目链里也是 | 应为"未指派"或者项目默认角色 |

| 7 | ~~非计划域里回车没反应~~ | 已修：纯文本在角色域开新建抽屉、项目域开 `project-new`，都把这段字当名字预填；设置域没有可提交的东西，输入框直接禁用并写明原因 | — |
| 8 | `done` 只有两态 | 勾掉 = 完成；想"取消/放弃"只能删掉 | 加 `skipped`，完成和放弃分开统计 |
| 9 | 权限开关**没有任何约束力** | 纯 UI | M3 的闸门 |
| 10 | 没有撤销 | 已加二次确认：计划列表那一行的垃圾桶点第一下变成红色对勾（4 秒后自己解除），详情页和项目页的删除按钮点第一下变成「确认删除」。角色本来就没有删除入口 | — |

## 6. 边角行为（不是业务，但会被误当成 bug）

- **吸附**：松手后才结算 —— 离屏幕边 12px 内停靠，否则留在原地。拖动途中既不磁吸也不因停顿而收起（靠 `GetAsyncKeyState` 判断左键是否还按着）。
- **位置记忆**：自由位置和停靠位置分别记；面板关闭后回到原来的停靠点，而不是面板留下的坐标。
- **失焦即隐**：面板丢焦点 280ms 后收起；二级窗口开着时不算。
- **右键菜单**：贴边药丸/展开清单上右键 → 重启 / 关闭（关闭 = 收起窗口，热键或托盘再唤出）。
- **托盘**：打开面板 / 关闭悬浮胶囊（关掉后这条自己变成「开启悬浮胶囊」）/ 退出。它是**开关**不是单向关闭：关 = 胶囊收起来，开 = 放回原来的停靠点。托盘和设置页是同一个开关，任一处改动都会同步另一处。

## 6.4 提醒（L1 / L2 / L3）

**时钟在内核里，不在前端。** 前端只把待执行的计划折算成**绝对时刻**（epoch 毫秒）推过去，因为它才知道时区和日历；内核只会比大小。

```
前端  $effect → invoke("set_schedule", { items: [{ id, dueAt, title, level }] })
内核  start_scheduler() 线程，每 20 秒对一次表
        ├─ L1 → 什么都不做（胶囊和日历已经承担了"看得见"）
        ├─ L2 → Windows 系统通知（tauri-plugin-notification）
        └─ L3 → 开那张置顶卡片（复用 popup 窗口，全局最多 1 张）
```

| 规则 | 说明 |
|---|---|
| 有效期 | due 之后 **10 分钟**内才响（`REMIND_GRACE_MS`）。关着 app 错过的就算了 —— 唤醒补偿是 M1 的事，开机把昨天一整天的计划挨个弹一遍更糟 |
| 去重 | 键是 `计划id:dueAt`。**把计划改到别的时间就是一个新槽位**，会重新响 |
| 每天重复 | 前端算 dueAt 时，如果今天这个点已经过了就 +24h。它每 30 秒重算一次，所以第二天自己会滚过去 |
| L3 排队 | 同时只留一张卡片。第二条 L3 不抢占也不吞掉，只是**这一轮不标记已响**，等卡片被答复后下一轮再响 |
| 强提醒不可 Escape | `onKeydown` 里 `isPopup` 直接 return —— 那张卡片就是用来"必须显式回应"的，误按一个键不算回应 |

**卡片上按完怎么办**：卡片自己不改数据（它是另一个 webview，内存里的计划列表不是同一份）。它只调 `answer_reminder(id, action)`，内核把卡片清掉、窗口收起来，再 emit `quorum://remind-answered`；**主窗**收到后改自己那份数据 —— 「完成」就是 `done = true`，「10 分钟后再提醒」就是把这条计划整体后移 10 分钟（start 和 end 一起，时长不变），于是 dueAt 变了、去重键也变了。

## 6.6 便签怎么变成计划（两条解析器）

草稿条那一张卡片是**确认步**，两种解析器往里填：

| 解析器 | 什么时候用 | 认得出什么 |
|---|---|---|
| **本地正则** `readPlan()` | 一定先跑；设置里关掉大模型、或大模型连不上时，它就是最终结果 | 只认数字时间（`9:30`）和「每天」 |
| **大模型** `parseNote()` | 配了接口地址时，正则出完草稿后再问一次（**没有开关**：确认卡片就是那道闸 —— 模型只提议，点「创建计划」的是人） | 自然语言：`明天九点半`、`重要，得提醒我`、`45 分钟`，以及这条该不该交给角色做 |

流程是 **先出本地草稿 → 再让大模型覆盖**：所以点下解析的那一刻卡片就在了（标着「解析中」），大模型回来就改字段，**没回来就保留本地结果**，并在卡片上写明「大模型没接上，用的本地解析」。

- 大模型只输出 JSON，字段一律在 `toDraft()` 里校验：日期要合格式、级别要在三个里、角色要真存在、`run` 没有指令就退回 `remind`。**它填错的东西进不来。**
- 请求发去 `{baseUrl}/chat/completions`，15 秒超时。前端直连（和设置页那个「测试连接」同一条路），**不经过内核**。

## 6.5 底部状态栏

面板底部那行现在报真实数据：左边是**最近一条还没到点的计划**（跨天取最近的），右边是**全部待执行条数**。30 秒自刷新一次，免得"下一项"停在过去。

它以前是写死的「下次触发 · 12:04 / 权限 · 2 项待授权」—— 一行字同时承诺了调度器和权限系统两件不存在的事。现在它只说已经排进去的东西，**不暗示会自己响**。

## 7. 设置与落盘

两个文件，内核只负责路径，形状归前端。

```
%APPDATA%\com.wenbuer.quorum\settings.json
{
  "capsule": "#e7f7fa",
  "floatingIcon": true,
  "hotkey": "Alt+Backquote",
  "llm": { "provider": "openai", "baseUrl": "…", "model": "…", "apiKey": "", "status": "ok" }
}

%APPDATA%\com.wenbuer.quorum\data.json
{ "plans": [...], "roles": [...], "projects": [...] }
```

| 字段 | 含义 |
|---|---|
| `capsule` | 悬浮窗底色（6 个预设 + 自定义取色），只允许浅色，因为胶囊的深色文字不跟着换 |
| `floatingIcon` | 是否显示悬浮胶囊。关掉后胶囊不再出现在桌面，**面板关闭时也不回来**（`restore()` 直接隐藏）；托盘那一项与它是同一个状态 |
| `hotkey` | 全局热键。**启动先读它**，被占用才回落到内置候选链，所以文件里存的可能是"实际生效的那个" |
| `llm` | 服务商 / 接口地址 / 模型 / 密钥 / `status`（没试过 / 通了 / 没通；由「测试连接」和每次便签解析写入）。便签解析已经真的走它（§6.6）；**角色执行还没接** |

- 写盘是**防抖**的（400ms），而且**先读后写** —— 否则启动瞬间的默认值会覆盖用户配置。
- `data.json` 一开始不存在是正常的：首次写入才创建。id 是 `p-1` 这种自增串，前端在载入后会把计数器推过已有最大值，再存才不会撞号。
- 这两个文件是**过渡形态**：M1 的 SQLite 会接手计划/角色/项目，设置也可能一起搬。
- 开机自启不在这里：它写的是注册表 `HKCU\...\Run`，状态以注册表为准。
- 大模型目前只有"配置 + 测试连接"，**没有任何角色真的调用它**。

## 8. 现在的"假"在哪

- 计划 / 角色 / 项目**已经真的落盘**（`data.json`，见 §7），重启不丢。种子里那几条演示计划已经删掉，空列表是真实状态。
- 到点会响了（§6.4），但**只在这个进程活着的时候**：关掉 app 期间错过的计划不会补响，那是 M1 调度器 + 唤醒补偿的事。
- 到点判定是"每 20 秒对一次表"，不是精确闹钟；机器休眠期间不响。
- 角色的 6 项权限开关没有任何约束力，纯 UI，等 M3 的闸门。
- 截图里那份等级色（L1 灰 / L2 蓝 / L3 橙）只是视觉分级，没有行为差异。
