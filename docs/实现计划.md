# AAIL 后续实现计划

## 0. 当前基线（M0 已完成）

- **外壳**：托盘、全局热键（Alt+` 优先 + 降级链）、单窗口三态（贴边 148×44 / 胶囊 320×44 / 面板自适应 40%×55%，夹在 760–1120 × 520–800）、二级独立窗口（全局 ≤ 1）、失焦即隐、贴边吸附（离边 12px 内且留得下就吸）
- **界面**：浅色单主题、计划总览（手机式月历：周一起始、可翻月、回到今天、展开有过渡动画；甘特图与任务列表两视图，甘特图横轴 24 小时、任务名在图形下方）、统一输入框（@ 选项目 / `/` 选命令、**命令可带参数**且已填参数显示为彩色小胶囊、失焦收起、默认聚焦）、角色页 + 2/3 宽抽屉编辑器、项目页 + 文件夹懒加载查看、悬浮胶囊右键菜单（关闭 = 收起窗口，热键或托盘再唤出）
- **工程**：移动盘存在性检测、镜像构建（TUNA / rsproxy）、安全 stop、架构图与设计稿

**关键欠账**：后端完全没接 —— 现在所有计划都是前端内存里的假数据，**重启即丢**。M1 就是来解决这件事的。

## 1. 三个必须先拍板的设计冲突

| # | 问题 | 建议 | 为什么现在必须定 |
|---|---|---|---|
| 1 | L3 强提醒窗 与 二级编辑窗 都是"抢注意力"的窗口，是否允许并存 | **统一为一个容量 1 的置顶交互窗池**，排队处理 | 决定窗口管理的数据结构，M2/M3 都要用 |
| 2 | 用户添加进来的目录若不是 git 仓库 | aail 代为 `git init`，还是只记操作日志不做版本控制 | M4 的前置；会动用户文件，不能替他决定 |
| 3 | 级联调用深度上限 | 按 **3** 走（A→B→C 到顶） | M5 的防环参数 |

## 2. M1 任务模型 + 调度内核（关键路径，其他都依赖它）

**目标**：任务成为一等公民，调度真的准。

**交付**
- SQLite 表：`tasks` / `runs` / `grants` / `audit`
- `Task{id, owner, created_by, when{kind: once|cron|after}, do{kind}, state}`
- Rust 到期调度器：最小堆 + 算 next-due 后 sleep（不忙轮询）+ **唤醒补偿**
- 命令：`create_task` / `list_tasks` / `complete` / `snooze`
- 前端接真数据：dock 倒计时改为"下一个到期任务"

**验收**
- 建一条"每天 9:15"，**关窗、锁屏、休眠唤醒之后**都能在 ±5 秒内触发
- 重启进程、重启电脑都不丢任务
- 系统时间被改 / 跨时区不重复触发

**风险**：休眠唤醒补偿、DST、时钟回拨。**必须用单调时钟 + 上次触发记录**，不能只靠 sleep 时长。

---

## 3. M2 三级提醒

**交付**：L1 角标（不抢焦点）/ L2 系统 toast / L3 自绘置顶窗（必须显式回应）；提醒分级器按级别分通道。

**验收**：三级各自可复现；L1 不抢焦点；L3 不回应不消失；同一时刻最多 1 条 L3。

**已知约束**：Windows 上 Tauri 官方通知插件**没有按钮**（Actions 是移动端专属）。所以 L2 只做"点击打开面板"，就地操作留给 L3。

---

## 4. M3 角色包 + 权限闸门 + 工作区边界

**目标**：把"权限下放"从口号变成机制。

**交付**
- `roles/<id>/role.json`（身份、触发、ops、权限声明）+ `work/` 初始化
- 角色加载器 + 注册表
- **边界判定**：命中（自有 work + 用户添加目录）→ 查改放行；未命中 → 冻结任务 → 弹窗请求授权 → 记住（角色 + 能力 + 路径前缀）
- 审计表：谁 / 何时 / 对什么 / 做了什么 / 结果

**验收**
- 角色只能碰自己的工作区，越界必弹窗，拒绝则任务转"已中止"
- 授权粒度生效：放行 `D:\Documents` **不等于**放行 `D:\财务`

**风险**：路径规范化。符号链接、`..`、大小写、UNC 都必须先 canonicalize 再比对，否则边界能被绕过。

---

## 5. M4 工作区 git 版本控制

**交付**：一次任务执行 = 一个 commit（message 含任务 / 角色 / 动作摘要）；commit 与 `runs` 关联。

**验收**：随便挑一次角色改动，能 `git log` 找到并回滚。

**前置**：第 1 节的决策 2。

---

## 6. M5 角色间调用（派发）

**目标**：A 能驱动 B，但 A 借不到 B 的权限。

**交付**
- `ops` 声明（id / callers / capabilities）
- 派发队列：异步、扇出、单个失败不阻塞其他
- depth ≤ 3 + visited 防环
- **输入安全落地**：解析产物严格 schema、动作白名单（`do.kind` 三选一，`run` 的工具必须已声明）、长度上限、速率限制

**验收**
- A 触发 B 执行成功
- **B 越权被拦**：有效权限 = 该 op 声明的能力，而不是 B 的全部权限
- A→B→A 自激被拦并记审计

**风险**：扇出风暴，需要并发上限。

## 7. M6 能力层

剪贴板、屏幕截图 + 本地 OCR、浏览器控制（独立 profile）、受限 shell、LLM Provider（Noop 起步，可切本地/云）。每个能力都过闸门。

浏览器控制必须**自带 profile 另起实例**：Chromium 系从 136 起收紧了远程调试端口对默认用户数据目录的 attach，挂不到你日常开着的浏览器上。

## 9. 零散欠账

- **任务生命周期图**：spec 已写好，HTML 因一个路由交叉过不了 showcase 校验，未交付
- 前端仍是内存假数据，M1 落地后替换
- 真人手拖仍只能人肉验证：合成鼠标事件进不了 Windows 的模态拖拽循环。但吸附逻辑本身可以测——用 `SetWindowPos` 从外部把窗口挪到离边 6px，内核的 `Moved` 处理会把它认成手动拖拽并对齐吸附
- **仓库自身的 git 与 M4 的工作区版本控制是两件事**：前者已经做了（`git init` on `main`，首个提交 `d96841b` 收下 M0 全部源码与设计稿）；后者是对**用户添加的项目目录**做 commit，仍未开始
- 三个待拍板决策仍开放（见第 1 节）

## 11. 验证手段（别用肉眼点）

两套脚本化验证，改完就能跑。

**1. 纯前端逻辑（浏览器）** —— 把 Vite dev server 当普通网页开，用 headless Chrome 的 CDP 驱动输入框：

```
powershell -File D:\aail-dev\aail.ps1 run pnpm tauri dev
node D:\aail-dev\drive.mjs
```

只覆盖路由、输入链、表单预填这类纯前端逻辑；Tauri API 会失败并被 catch 吞掉。

**2. 真机窗口（Tauri）** —— 给 WebView2 开调试端口，就能在真实窗口里读 DOM、触发点击、截图：

```
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS='--remote-debugging-port=9444'
powershell -File D:\aail-dev\aail.ps1 run pnpm tauri dev
node D:\aail-dev\appcheck2.mjs   # 断言脚本
node D:\aail-dev\appcheck3.mjs   # 截图脚本（Page.captureScreenshot）
```

页面里的入口是 `window.__TAURI_INTERNALS__.invoke(...)`，所以 `set_mode` / `list_dir` 都能直接调。

**两个坑**：

- 合成鼠标（`SetCursorPos` + `mouse_event`）只挪得动光标，点不动 webview，也点不动原生菜单：窗口内点击走 CDP，系统菜单走键盘（`{DOWN}` 再 `{ENTER}`）。键盘本身是好的，`SendInput` 的 Unicode 模式能送中文，`SendKeys` 送不了。
- Vite 的 HMR 会静默失效：改完前端如果行为不像新的，先重启 `pnpm tauri dev`，别怀疑代码。
